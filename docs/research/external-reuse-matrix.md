## 2. Methodology & Compliance Rules

Every candidate evaluation strictly adheres to EcoSite India's architectural boundaries:
1. **Zero Unverified Risk:** Missing or failed source data must map to `UNKNOWN` or `SOURCE_UNAVAILABLE`, never zero risk or synthetic defaults.
2. **No Opaque ML Predictors:** No `.pkl` imports, no black-box site suitability classifiers without genuinely independent labelled ground truth.
3. **No Unlicensed Code Ingestion:** If licensing is missing or ambiguous (e.g., `AquaLytics`), raw code copying is strictly **REJECTED**; only textbook scientific formulas may be clean-room reimplemented.
4. **No External Dataset Ingestion:** External CSV dumps or `.tif` rasters are not copied into EcoTerminal; real observation pipelines must rely on versioned connectors (Siddharth) with explicit provenance.
5. **Separation of Scopes:** Candidate site screening operates on user-defined polygons (Phase 02B), cumulative milestone development phases (Phase 02C), and deterministic evidence graphs (Phase B).

## 4. Top Five Highest-Value Reuse Opportunities

Ordered by practical MVP benefit for EcoSite India:

### 1. Scientific Audit Engine & Comparative Assertion Blocker (`OpenDC-LCA`)
* **Source:** `OpenDC-LCA/src/opendc_lca/audit.py` (`audit()`)
* **Decision:** **ADAPT**
* **Why it matters:** EcoSite’s core value proposition is explainable, evidence-backed pre-investment screening. `audit.py` provides a ready-made, zero-dependency pattern to deterministically block comparative assertions if a site relies on synthetic data, lacks quantified uncertainty, or contains unreviewed document claims. It directly implements the `AGENTS.md` rule: *"Missing/failed source data means UNKNOWN / SOURCE_UNAVAILABLE, never zero risk."*
* **Target:** `backend/app/domain/evidence/audit.py` (supporting Phase B and Phase F Passport generation).

### 2. Evidence Data-Source Provenance Registry (`OpenDC-LCA`)
* **Source:** `OpenDC-LCA/src/opendc_lca/models.py` (`DataSource`, `StudyDefinition`)
* **Decision:** **ADAPT**
* **Why it matters:** Phase B requires private `EvidenceArtifact` and `Assertion` contracts. Adapting `OpenDC-LCA`'s `DataSource` schema gives EcoSite an established structure for citations, geographic scope, reference years, review statuses (`unreviewed`, `internally_reviewed`, `independently_reviewed`), and confidentiality levels (`public`, `confidential`).
* **Target:** `backend/app/schemas/evidence.py` and `backend/app/data/models.py` (Phase B foundation for Krishna and Samarth).

### 3. Outlier-Resilient Percentile Clipping & Normalization (`Loadstar`)
* **Source:** `Loadstar/backend/engine/normalization.py` (`percentile_bounds()`, `normalize_value()`)
* **Decision:** **ADAPT**
* **Why it matters:** Comparing candidate sites across heterogeneous environmental and utility dimensions (e.g., substation distance in km, water occurrence in %, slope in degrees) requires robust normalization. `Loadstar`’s $P_5–P_{95}$ percentile clipping avoids distortion from extreme outliers, handles zero/degenerate ranges safely, and respects directionality without needing external scientific packages.
* **Target:** `backend/app/domain/scoring/normalization.py` (Phase F 3-site comparison engine).

### 4. Two-Tiered Site Screening: Hard Gates + Multi-Factor Traceability (`Loadstar`)
* **Source:** `Loadstar/backend/engine/scoring.py` (`eligible_sites()`, `_score_site()`)
* **Decision:** **ADAPT**
* **Why it matters:** Prevents the dangerous anti-pattern of allowing high scores in one area (e.g., low land cost) to mask disqualifying physical barriers (e.g., zero available MW, flood-plain overlap, or state boundary violation). Hard gates eliminate unviable sites first; viable sites receive an additive score with explicit per-factor point contributions and human-readable units.
* **Target:** `backend/app/domain/readiness/scoring.py` (Phase F Readiness runs).

### 5. Deterministic Rainwater Harvesting Offset Calculator (`AquaLytics` Physical Principles)
* **Source:** `AquaLytics/rwh.py` (Textbook Rational Method: $Q = P \cdot A \cdot C$)
* **Decision:** **REIMPLEMENT (Clean-Room)**
* **Why it matters:** Indian municipal building codes (e.g., Maharashtra Unified DCR, Karnataka Model Building Bye-laws) mandate on-site rainwater harvesting for plots exceeding 500–1,000 $\text{m}^2$. Clean-room reimplementation of the standard hydrological formula allows EcoSite to calculate daily and annual KLD rainwater capture potential from campus roof and hardscape areas, directly evaluating if on-site harvesting can offset cooling water deficits under Phase 02C water allocations.
* **Target:** `backend/app/domain/resources/water_offset.py` (Phase C Water Readiness).

## 5. Unresolved Licensing & Provenance Risks

1. **`AquaLytics` License Absence:**  
   While the README asserts "MIT License", the repository contains no `LICENSE` file and appears to be an unmaintained SIH 2023 student project. **Zero lines of code should be copied from `AquaLytics`.** Only textbook hydrological equations (BIS IS 15797:2008 / NBC 2016) should be clean-room implemented.
2. **`AquaLytics` Silent Missing Data Imputation:**  
   `AquaLytics` silently replaces `'N.A.'` groundwater readings with `10` mbgl. Reusing this logic in EcoSite India would create severe legal and technical risk. All missing readings must remain `UNKNOWN` / `SOURCE_UNAVAILABLE`.
3. **`AquaLytics` Pickled Model Security Vulnerability:**  
   `aquifer_recommendation_model.pkl` is an opaque binary pickle. Importing it risks arbitrary code execution and violates the strict prohibition against black-box approval predictors. It is permanently **REJECTED**.
4. **`CERF-DC` Regional & Unit Incompatibilities:**  
   `cerf_data_centers` hardcodes US-specific projections (`ESRI:102003`), imperial units (sq ft, $/kWh, gallons/MWh), and US tax mechanisms (personal property tax). Direct adoption without extensive refactoring would corrupt Indian unit semantics.
5. **`Loadstar` European Grid Assumptions:**  
   `Loadstar`’s power optimizer assumes European nodal pricing and ENTSO-E market dynamics. In India, open-access renewable power involves captive vs. third-party PPA rules, Green Energy Open Access (GEOA) charges, and state-specific banking restrictions. The LP mathematical formulation is sound, but cost coefficients and constraints must reflect Indian regulations.
